Computer vision foundations · Lesson 02

Images are data

The same red pixel can look blue to a model if we hand over its numbers in the wrong order. Let’s prepare one image without changing what its numbers mean.

Core: about 15–20 min; optional notes extraBasic programming only

Your goal: describe an image’s color order, array shape, and value range, then trace those choices into the input code.

1. A picture becomes a grid

A digital image is a grid of pixels: samples representing small areas of the picture. A channel stores one kind of measurement at every pixel. RGB means red, green, and blue channels. One RGB pixel might contain [200, 40, 10]: a strong red value, less green, and little blue.

These values depend on the light, the surface, and camera processing. Exposure is how much light the camera collects for an image. A cube in shadow can produce different numbers from the same cube under a bright lamp. A red value alone cannot tell us whether the object is a cube.

Coordinates identify a position. Here, x counts columns to the right and y counts rows downward, starting at zero in the top-left. An image array commonly uses image[y][x]: row first. Our tiny image has height 2 and width 3; its last column has x = 2, not 3.

2. Shape, channels, and batches

Here, a tensor means a numeric array with one or more axes. An axis is one direction of indexing; the tensor's shape lists the size of each axis. The image above has shape [2, 3, 3]: 2 rows, 3 columns, 3 color channels. Three array axes do not mean that the image contains three-dimensional positions. Source: PyTorch tensor introduction.

HWC means height, width, channels, in that axis order. CHW means channels, height, width. Transposing rearranges axes: HWC [2, 3, 3] becomes CHW [3, 2, 3]. A channel plane is the grid of all values for one channel. In CHW, the three color planes come first.

BGR means blue, green, red. It describes color order, whereas HWC describes axis order. Our selected pixel is RGB [200, 40, 10] or BGR [10, 40, 200]. Both describe the same color when interpreted correctly. Reading BGR numbers as RGB would instead make this pixel blue-dominant. OpenCV, an image-processing library, commonly uses BGR for loaded color images. Source: OpenCV image tutorial.

What does the N axis mean?

A batch is a group of images passed to a model together. The batch axis lets you select which image you mean, just as the row axis lets you select which row you mean. Adding this axis wraps the image array in an outer collection of images.

In the name NCHW, each letter names an axis: N counts images in the batch; C counts channels per image; H counts rows per channel; and W counts columns per row. These counts, in that order, form the array's shape.

Worked example: put two of our tiny RGB images in one batch. Each image has three channels, two rows, and three columns, so the NCHW shape is [2, 3, 2, 3]. Its N-axis size is 2 because there are two images. Their indices are 0 and 1: an axis size counts how many items exist, while an index selects one item. The number of objects pictured inside an image does not change N.

With just one image, the outer collection still exists but contains one item. For example, one RGB image of 480 rows and 640 columns has NCHW shape [1, 3, 480, 640].

3. Change the scale of the values

A data type specifies how numbers are stored. An 8-bit unsigned integer, often called uint8, uses eight binary digits and stores whole numbers from 0 to 255. float32 uses 32 binary digits for a floating-point number: it supports fractional values, with limited precision.

Normalization rescales values according to a chosen rule. For a model expecting values from 0 to 1, convert to floating point and divide by 255. Our RGB pixel becomes [200/255, 40/255, 10/255] ≈ [0.784, 0.157, 0.039]. The symbol ≈ means approximately equal. This changes the numeric scale; it does not correct lighting. Other models may require different rules.

Why isn't 128 exactly 0.5?

The divisor is 255, so 128/255 is approximately 0.502. Values 0 and 255 map exactly to 0 and 1. Normalizing is a representation change; moving this slider changes the actual channel measurement.

The input contractA contract is the set of expectations that two pieces of software must share. For an image, specify axis order, color order, data type, value range, and any changes to positions. A correctly running model can still predict badly when those expectations are violated.

Extension: resize positions and check a complete input

4. Resize without losing track of positions

Resizing changes image width and height. Aspect ratio is width divided by height. Stretching a wide image into a square changes that ratio and distorts shapes. Letterboxing keeps the ratio by scaling width and height by the same factor, then adding a border called padding.

Worked example: fit a 640-wide, 400-high image into a 320 × 320 square. The scale factor—new size divided by old size—is 0.5. The image becomes 320 × 200. Centering it leaves 120 rows of padding: 60 above and 60 below.

A bounding box is a rectangle marking an object's image location. Its coordinates must follow the resize and padding too. For a box corner originally at (x, y) = (100, 40):

new x = old x × 0.5 = 50
new y = old y × 0.5 + 60 = 80

To return a predicted corner to the original image, undo padding first, then scaling: old y = (80 − 60) / 0.5 = 40. These formulas describe box coordinates, not the details of how a resizing algorithm mixes pixel colors. Source: OpenCV image transformations.

Applied to our cubes

Preprocessing is the preparation done before inference. A ROS 2 node is a software component participating in a robot's communication system; ROS 2 stands for Robot Operating System 2. Our detection node receives images and prepares their arrays for the model.

Verified in the current code: it reverses BGR to RGB, letterboxes (resizes proportionally and adds padding) to the configured square input size, converts to float32 and divides by 255, transposes to CHW, then adds the batch axis. The documented model input is [1, 3, 640, 640]: one image, three channels, 640 rows, 640 columns. The optional resizing example uses a smaller square to make the arithmetic easy.

Read the input preparation in the detection node and documented model input as project examples. Neither RGB nor 640 × 640 is a universal requirement for all models.

Implemented in training configuration: the fine-tuning script sets these command-line defaults. A default is used unless the person running the script supplies another value:

batch requests 16 images per training batch; it is unrelated to the number of cubes in each image. imgsz requests training image size 640. The script passes these settings to the training library, which prepares the training tensors; it does not spell out that preprocessing itself. A final batch can contain fewer images.

Implemented at robot inference: _infer() makes value scaling and axis preparation visible. Here np is the code’s short name for NumPy, a library for numerical arrays:

Runtime input preparation · _infer() · selected source lines:

img = img.astype(np.float32) / 255.0
img = img.transpose(2, 0, 1)
img = img[np.newaxis, ...]

These selected lines convert values to float32 and normalize them, rearrange HWC to CHW, and add the N axis. np.newaxis inserts a size-one axis; ... retains all existing axes. The omitted intermediate line arranges memory for the runtime.

Trace this code: does training batch 16 mean the robot needs 16 cameras?

No. A batch groups training examples. This runtime path processes one image at a time and adds a batch axis of size one.
