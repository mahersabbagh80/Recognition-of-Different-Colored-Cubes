Transfer learning and augmentation

Reuse a visual representation, adapt the task-specific output, and transform examples only when their labels remain true.

Your goal: judge whether a transferred model and image transform preserve the cube task.

1. Transfer learning has a source and a target

Suppose a source model already sees edges and shapes, but your new camera must recognize blue, green, and red cubes. Reusing those starting features may save data and time, but only target examples can show whether the new camera and class definitions work.

Transfer learning adapts a model whose parameters were learned for a source task and dataset to a target task and dataset. A pretrained model is that starting model. Its backbone extracts visual features; its task-specific output layer turns them into class scores and bounding boxes, rectangles locating objects. Transfer is a starting strategy, not proof of success.

Central mental modelSource data provides a visual starting point. Target data teaches the new categories, locations, and camera conditions. Held-out target examples decide whether the transfer helped.

2. Freeze or fine-tune?

To freeze parameters means to keep them fixed during a training run. A common fixed-feature plan freezes the backbone and trains a new output layer for the target classes. Fine-tuning means continuing to update some or all pretrained parameters with target data. Fine-tuning can adapt more of the representation, but a small or biased target dataset can overfit or damage useful starting features.

Overfitting means adapting to training examples in ways that do not work well on new examples. Training loss is the numerical error used to adjust parameters. A validation rule compares candidate models on examples withheld from parameter updates; it guides which model to keep.

The choice is an experiment. Record which layers were frozen, which output was replaced, what target data was used, and which validation rule selected a checkpoint. A checkpoint is a saved snapshot of learned parameters and related training state. A lower training loss or a saved file does not, by itself, show that target-camera performance improved.

3. Augmentation is a label-preserving claim

Data augmentation creates an additional training example by transforming an existing example. The transformation is valid only if the target remains true and every attached annotation, such as a class and box, moves consistently. A horizontal flip mirrors an image left-to-right; a resize changes pixel dimensions; a crop keeps only a selected region.

For detection, the box must move with the object. Let the image width be W, the original box's left coordinate be x, top coordinate be y, width be w, and height be h. Coordinates count pixels from the top-left. After a horizontal flip, the new left coordinate is x′ = W − x − w; y, w, and h stay the same. The prime mark ′ means “after transformation.”

Worked example: an image is W = 100 pixels wide. A cube box is x = 20, y = 25, w = 30, h = 20. The flipped box starts at x′ = 100 − 20 − 30 = 50, so it covers horizontal pixels 50 through 79 under a zero-based, half-open convention. “Half-open” means the start is included and the end is excluded; the geometric width is still 30. If the image is flipped but the box remains at x = 20, the training annotation points to the wrong place and teaches the wrong relationship.

4. Decide which transformations fit the task

An augmentation encodes an assumption about deployment, meaning use of the selected model in its intended real environment. If a cube can appear on either side of the image, a horizontal flip may preserve its class and box after the box transform. If color names define the classes, swapping RGB channels changes red into blue and does not preserve the target. RGB means red, green, and blue image channels. Exposure is the amount of light recorded by the camera. Translation is moving image content to a new position. Blur is a smoothing operation that removes fine detail. A heavy blur may be useful only if the camera really produces that blur and enough shape evidence remains.

Domain adaptation means adapting a model to a different domain, a recurring combination of camera, scene, lighting, and object conditions. Augmentation can simulate variation, but representative target recordings are stronger evidence. Keep a held-out evaluation set, meaning examples reserved from training and choice, so a transformation is judged by observed behavior.

HSV is a way to describe color with hue (the color family, such as red or blue), saturation (color intensity), and value (brightness). HSV jitter changes pixels; it does not rename a target class. Mosaic combines four training images into one composition, while MixUp blends two images and their labels. Both can be useful, but the resulting boxes and color evidence still need inspection.

model = YOLO(args.base)

    mosaic=1.0,
    mixup=0.15,
    hsv_h=0.015,
    hsv_s=0.7,
    hsv_v=0.4,
    close_mosaic=10,
    degrees=10,
    fliplr=0.5,

The YOLO(args.base) load and augmentation arguments are implemented settings for this run: hsv_h=0.015 varies hue by a small fraction of the color wheel, hsv_s=0.7 varies saturation, and hsv_v=0.4 varies brightness. mosaic=1.0 requests four-image compositions whenever mosaic is active; close_mosaic=10 disables mosaic for the last ten epochs. mixup=0.15 requests two-image label blending with probability 0.15. The model is loaded first; these arguments belong to the subsequent training call.

These values are configured requests, not proof that the outputs are useful or invalid. Render a small sample with its boxes and class names, then inspect whether red, green, and blue cube labels remain visually defensible and whether packaging is still a distractor. Compare the selected run on a held-out target session before changing the settings. A color shift may remain label-preserving when the class is still clear; a setting should be rejected when the rendered evidence or held-out behavior shows otherwise.
