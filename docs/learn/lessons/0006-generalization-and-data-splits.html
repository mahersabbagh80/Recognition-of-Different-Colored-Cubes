1. Fitting is not generalizing

Imagine a video of one cube on a desk: 600 frames can look like 600 examples, but neighboring frames may show nearly the same pixels. If those frames are split carelessly, a validation score can look excellent while the robot still fails in a new room.

Fitting adjusts a model to match training examples. Generalization means useful predictions on new examples from the conditions the system must handle. Overfitting means matching accidental training details and then performing worse on relevant new data.

A data split assigns examples to separate jobs. The training set may change learned parameters; the validation set is held out while parameters update and guides choices; the test set stays untouched until choices are finished and estimates the selected system under its recorded conditions.

SplitPermitted useQuestion it answers
TrainUpdate parametersCan the model fit the supplied examples?
ValidationCompare choicesWhich setting or checkpoint looks better before final reporting?
TestNo tuning or selectionHow does the selected system perform on this untouched sample?

Data leakage is unwanted information crossing a boundary so that a held-out result influences training or selection. Inspecting test failures, changing the model, and then reporting that same test as final evidence is leakage by selection. Once the test has guided a change, it is serving a validation role; reserve a new untouched test if an honest final estimate is needed. You may repeat measurements of a fixed system, but do not use those test results to choose the system.

Central mental modelTrain changes the model. Validation changes your choices. Test changes neither; it measures the chosen system once under known conditions.

2. Why the split unit matters

A capture session is one recorded camera setup or continuous recording with shared conditions. A video frame is one image at one time. Neighboring frames often share the same viewpoint, lighting, background, and object position. If individual frames are shuffled randomly, near-duplicates can land in train and validation. The filename looks new while the visual situation is familiar.

Session splitting keeps every frame from one capture session in one split. Deployment means using the selected model in its intended real environment. You can also group by physical object, room setup, or day when that matches the novelty expected after deployment. The correct grouping unit is a design decision: ask what should count as “new” for the robot.

Distribution shift means the mix of conditions changes between the data used for development and the data seen in deployment. Lighting, camera height, distance, background, and object presentation can all shift. A random frame split can hide that shift; a held-out robot-room session can expose it.

3. Overfit curves and small samples

A training curve plots a value over progress, often by epoch, one complete pass through the training examples. A loss is a numeric penalty for disagreement between prediction and target. Training loss can fall while validation loss first falls and then rises; that turning point is evidence that continued fitting may be memorizing details that do not transfer. A small validation sample makes the estimate noisy: one changed prediction can move the percentage a lot.

Worked example: suppose a validation set has 10 images, exactly one target cube in each image, and the model finds 9 of those 10 cubes. Recall is the fraction of real targets that were found, so object-level recall is 9 ÷ 10 = 0.90. If one image is removed and the one missed cube was in it, the reported recall becomes 9 ÷ 9 = 1.00. The arithmetic is correct, but the small sample gives a wide sense of uncertainty. A number is not more reliable merely because it has two decimal places.

4. Hard negatives reveal shortcuts

A negative example contains no target object. A positive example contains at least one target object. A hard negative is a negative that looks temptingly like a target, such as a blue package when the target is a blue cube. Including hard negatives teaches the model which visual differences matter. It cannot replace positive examples, clear labels, or a deployment-representative test.

A false positive is a predicted target with no matching target. A false negative is a missed target. Occlusion means that part of an object is hidden by something in front of it. If the dataset contains only obvious empty backgrounds, false positives caused by colored distractors may remain hidden. A balanced evaluation should include empty scenes, real cubes, occlusion, lighting changes, and look-alikes.

Final challenge · a flattering score from one scene

The builder has 30 cubes frames and 30 empty frames from the same stationary JetRover scene, plus crops from that scene. It writes val: ../images/val and test: ../images/val, and a model scores 98% on both. What should you say before using that number to claim robot-room performance?

Worked reveal and rubric

The two paths are aliases for the same validation images, and the 60 JetRover frames plus crops repeat one physical scene. The 98% is therefore development evidence under those conditions, not an independent final estimate of a new room. Capture a fresh robot-room session with changed conditions, keep it whole and untouched during training and model choice, and report those conditions with the result. Shuffling neighboring frames would preserve the leakage risk.
