How models learn

Our color rule makes mistakes. See which numbers we can adjust, and how examples supply the answers we want it to learn.

Your goal: trace one model prediction from a redness feature to a cautious decision.

1. From hand-written rules to adjustable parameters

Suppose you show a program ten photos labelled “red cube” and ten labelled “not a red cube.” You want it to make a sensible guess on the next photo, even though nobody has supplied that answer yet. That is the small problem this lesson models.

In supervised machine learning, examples come with desired answers called targets. A model maps an input to a prediction; training changes adjustable numbers so predictions fit the examples, while inference uses the current numbers to predict without receiving the target. A label is a category name such as “red cube”; a target may also include a bounding box, the rectangle locating an object.

A parameter is a number training may change. A feature is one input measurement that carries useful evidence. We will use the deliberately incomplete feature x = redness, where x stays on a toy scale from 0 to 1. Settings chosen outside the learned parameters are hyperparameters; the learning rate used later is one example.

Central mental modelExamples and targets provide supervision. Parameters define the current rule. Training changes parameters; inference applies the current rule without seeing the target.

2. A one-feature score

Let w be a weight, which scales the feature, and b be a bias, which shifts the result even when the feature is zero. The raw score is z = w×x + b. The letter z is only a name for this intermediate number. A positive score supports the chosen class in this toy model; a negative score argues against it.

Worked example: with redness x = 0.8, weight w = 4, and bias b = −2, the score is z = 4×0.8 − 2 = 1.2. A sigmoid is a smooth function that maps any real score to a number between 0 and 1: σ(z) = 1 / (1 + e−z). The symbol σ means sigmoid, and e is the fixed mathematical constant about 2.718. A probability is a number from 0 to 1 used here to express the model's estimated support for a class, not certainty. Here σ(1.2) ≈ 0.769, so the model reports about 0.769, or 76.9%, as its predicted probability for the selected class under this toy interpretation.

That number is a prediction, not a guarantee. It is meaningful only relative to the examples, model, preprocessing, and conditions that produced it. If a red ball has the same redness feature as a red cube, this model cannot tell them apart. A probability near 0.77 does not prove that the object is a cube, and a threshold such as 0.5 is a decision rule chosen by an engineer, not a truth meter.

Predict the direction: the redness input stays between 0 and 1. If the weight is positive, increasing redness increases the score; if the weight is negative, increasing redness decreases it. For instance, at bias 0, raising x from 0.5 to 1 changes z from −1 to −2 when w = −2. At zero weight, changing x has no effect. Increasing the bias always increases z; increasing the weight increases z when x is positive.

3. Labels, targets, and checkpoints

For image classification, a target might be one label such as “cube present.” For detection, it includes the class and a box for each object. This recorded target is an annotation; a dataset is the organized collection of examples and annotations. Inconsistent annotations, such as ignoring some partly hidden cubes without a stated policy, make the desired rule unclear.

Annotation inspection: before training, look at the image and its labels together. Count each visible target, check that its class name is correct, and check that its box encloses that object tightly. This whole frame is a positive detection image because it contains cubes; the package remains unannotated background within that image. Only a separately cropped, verified cube-free region can be used as a hard-negative example with an intentionally empty label file. A missing label file is an ingestion problem, not proof of an empty scene.

A checkpoint is a saved snapshot of model parameters and related training state. It is not automatically the best snapshot. A checkpoint rule can select the epoch, one complete pass through the training examples, with the best result on a validation set, data held out while parameters update. The next lesson explains why a final test must stay separate.

4. Probability changes are not truth changes

A decision threshold is a chosen cutoff that turns a continuous score into an action such as “accept” or “reject.” It can be moved when the costs of false positives and false negatives differ. A false positive is an accepted prediction with no matching target; a false negative is a missed target. Changing the threshold changes these decisions without changing the model's learned parameters.

The decision rule: accept when the predicted probability is greater than or equal to the threshold; otherwise reject. For example, prediction 0.60 is accepted at threshold 0.50 but rejected at threshold 0.70. Equality is accepted by this toy rule.

5. Applied to our cubes

Fine-tuning continues training a saved model. Hard negatives are non-target examples that resemble targets, such as colored packaging that is not a cube.

Current code: the repository’s runnable hard-negative entry point loads a detector and asks the Ultralytics library to train it. YOLO means “You Only Look Once,” a family of detectors that predicts classes and image locations. The YOLO class and its train method come from Ultralytics; this repository configures their call.

Selected lines, with the other training arguments omitted:

model = YOLO(args.base)
results = model.train(
    data=args.data,
    # other training arguments omitted
)

YOLO(args.base) and model.train(...) connect the lesson’s terms directly: the loaded checkpoint supplies current parameters, while labeled examples and training settings let the library adjust them. args.base selects the starting saved model; args.data selects the dataset configuration, the file listing image splits and class names. The script’s --base default is models/best.pt. This is learned fitting, not a hand-written rule such as “if redness > T.”

Annotation audit: build_hardneg_dataset.py stores three fixed CUBE_BBOXES and build_jetrover_positives writes those three labels into every copied JetRover frame. Its build_jetrover_hardneg_crops function creates separately cropped distractor images and intentionally writes empty label files. The script comments call the red box confirmed and the green and blue boxes estimated. That is an implemented shortcut for this capture; it is a reason to inspect representative frames and label files, not proof that every box is correct.

Proposed improvement: if the baseline fails on robot-room images, run a controlled fine-tune and judge it on a held-out capture, save checkpoints during training, and select one for deployment only after inspecting its evaluation results. That evaluation step is not implemented by this lesson.

Worked reveal and rubric

Start with the image, not the file name: count the three visible cubes, verify red/green/blue class names and box geometry, and leave the package unannotated because it is background in this positive image. If you crop a region and verify that it contains no cube, an intentional empty label file can make that crop a hard negative; an absent label file cannot establish that claim. Fixed coordinates can repeat a labeling error, so a checkpoint cannot repair a wrong target.
