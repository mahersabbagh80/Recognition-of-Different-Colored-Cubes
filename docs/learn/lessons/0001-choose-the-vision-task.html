Computer vision foundations · Lesson 01

Choose the vision task

Start with the answer you need from an image. Then choose the kind of vision system that can produce it.

Core: about 15–20 min; optional notes extraBasic programming only

Your goal: distinguish image classification, object detection, and segmentation, then write a small specification for a vision task. Every term needed for that decision is introduced below.

1. What are we asking the computer to do?

A sorting station asks for “cube recognition.” Before choosing software, ask what its screen should show: a category name, a rectangle around every cube, or the exact outline of each one? Those are different jobs.

Computer vision is the field of extracting useful information from images or video. A video is a sequence of images called frames. A digital image is a grid of small samples called pixels. The camera records measurements; the software must turn them into an answer.

Optional: where machine learning fits

Machine learning is a way of building computations whose adjustable values are learned from examples. A model is the computation that maps an input to a predicted answer. Training adjusts it using examples; inference applies it to produce predictions. Computer vision can use machine learning or programmer-written rules. The task describes the answer required, not which implementation must produce it.

Imagine a camera watching a sorting table. “Understand the objects” could mean: say which categories are present, locate every object, or mark the pixels belonging to each category. Those requests need different outputs.

The decision to make firstWhat information must the next person or program receive? Choose a task that supplies that information before choosing a model.

2. Three answers to the same picture

Our project needs separate class-and-box detections. Classification and masks below are a short comparison to clarify that choice; we will not train a segmentation model in this course.

A class is a category, such as “red token.” A label is the name or identifier used for that category. An object instance is one particular object: two red tokens are two instances of the same class.

Image classification assigns a category to an entire image. Multi-label classification allows several categories for one image. It can report that red tokens are present, but an image-level label does not specify each token's location or count.

Object detection predicts individual objects, usually with a class, a bounding box (a rectangle enclosing an object's image location), and a score (a number expressing the model's support for that prediction). A high score is not proof that the object exists or that the box is correct.

Semantic segmentation assigns a class to each pixel. A mask is an image-sized grid recording which pixels belong to a class or object. Background means the image regions outside the target categories. Semantic segmentation distinguishes categories; instance segmentation additionally separates individual objects of the same category. Predicted masks can be wrong, just as predicted boxes can be wrong.

The drawings show idealized outputs for the same scene. In the segmentation panel, purple and gold represent assigned classes, not measured camera colors. Real masks may use any display colors. Detection gives rectangles, which can include background; a mask describes the visible shape more closely.

These are standard task distinctions, also reflected in the Torchvision task catalogue.

With either one or two red tokens, classification gives the same category list. Detection supplies separate boxes. Semantic segmentation marks the class regions without assigning separate identities to the two tokens. With zero tokens, “red token” should disappear from the answer.

3. Work backward from the requested answer

Worked example: a sorting station only needs a yes/no answer: “Is any red token visible?” An image classifier with the labels “present” and “absent” supplies the required information. A detector could also answer this, but separate object locations are unnecessary for this request.

Now the screen must draw a rectangle around each token. Classification no longer supplies enough information. Detection supplies separate boxes. If the screen instead needs to color every visible token pixel, segmentation fits that output. If two touching tokens must have separate masks, choose instance segmentation.

A coordinate is a number used to specify position. A box's image coordinates locate something on the picture, not in the room. 2-D means two-dimensional, such as horizontal and vertical image position. 3-D adds a third spatial dimension. A robot arm may need a position in physical units and a pose—position together with orientation. Choosing detection alone does not solve that additional measurement problem.

4. Make the task testable

An input/output contract is an explicit agreement about what enters the system and what answer it must return. A specification records that agreement and its conditions. Here is a small example for the sorting table:

  1. Input: one image from the fixed camera.
  2. Output: a list containing one class and one box for each visible token; an empty list when none are present.
  3. Operating conditions: the lighting, viewing direction, distances, and clutter the system is expected to handle. For this example: overhead camera, indoor light, separated tokens.
  4. Success criterion: a measurable requirement. For a small demonstration: in ten prepared scenes, mark every visible token once and never mark a tile as a token.

This small check is a demonstration, not a reliability estimate. Evaluation compares predictions with reference answers. An annotation records such an answer, for example a human-drawn box and its class. Decide consistently whether partly hidden cubes should be annotated.

Include images with no target objects and with look-alikes. A false positive is a prediction of a target where no matching target exists; a false negative is a missed target. Seeing only easy positive examples would hide these failures. Later lessons explain precise counting rules.

Guided check: name the output

Choose the task that directly supplies the requested output. Other systems might produce extra information; focus on what is needed here.

1. Report whether any damaged package is present in a photograph.

2. Draw a separate rectangle around every package.

3. Mark every visible pixel belonging to a package.

Worked answers

1. Classification: the answer applies to the whole image. 2. Detection: separate rectangles locate individual objects. 3. Segmentation: the output must identify pixels. For separate masks of individual objects, specify instance segmentation.

6. Applied to our cubes

Project requirement: identify red, green, and blue cubes while rejecting other colored objects. The categories describe both color and shape. A red ball should not become a red-cube detection merely because its color matches.

Verified code behavior: the current system produces a list of detections containing class names, scores, and boxes. A message is a structured package of data sent between software components. The detection messages carry image locations. This makes object detection a suitable task for the project's requested output.

The project definition excludes robot navigation and manipulation—moving the robot around and moving objects with it. Do not interpret a drawn box as evidence that a robot can already grasp a cube. See the current detection-message construction for the implementation.

Optional: follow this concept into the source code

Read the project code

Implemented in dataset preparation: convert_label_line() in the label-conversion script turns a polygon (an outline made of connected points) into an axis-aligned box, whose sides follow the image rows and columns. Here minx/maxx are the leftmost/rightmost outline coordinates, and miny/maxy are the top/bottom ones. The code derives the box center and size:

Label conversion · convert_label_line() · selected source lines:

cx = (minx + maxx) / 2.0
cy = (miny + maxy) / 2.0
w = maxx - minx
h = maxy - miny

This makes the training answers suit detection. The resulting rectangle no longer records the detailed object outline needed for segmentation. The class stays attached to the box.

Possible next step: inspect converted boxes against their images before training. If the task later requires precise masks, retain the original outlines and use a segmentation training workflow.

Trace this code: what information is lost?

The box keeps the outer limits, but loses the exact outline between them. Training on these boxes does not teach a pixel-by-pixel mask.

The screen must report how many individual cubes are visible, even when they have the same color. An image-level category list says only which categories are present.
