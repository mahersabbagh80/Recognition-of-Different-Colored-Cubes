Optional robot track · Lesson 13

Can we trust this depth?

A number inside a detection box may belong to the cube, the floor, or no valid measurement at all.

Core path: about 15–20 minutes · optional notes take extra time

This lesson is optional for the training course. Study it when you are ready to integrate the selected detector with the robot.

Your goal: decide when depth supports a geometry check and when the evidence is insufficient.

1. Check what the depth numbers mean

A depth image stores a distance value at each pixel. A pixel is one image sample. In this lesson optical Z measures distance forward along the camera’s central axis; a larger value means farther away along that axis. RGB names the red, green, and blue color channels. A bounding box is the rectangle enclosing a detected object.

Before comparing a cube and the floor, check units, missing values, and registration: whether a depth sample corresponds to the same scene location as its RGB pixel. Two equally sized images can still be misaligned.

2. Choose a useful sample

Suppose the stored value is 1050. If the image uses millimetres, that is 1.05 metres. If you read it as metres, the geometry is wildly wrong. This exercise uses unsigned 16-bit integers (uint16) in millimetres, with zero marking an invalid reading. Other depth streams use fractional values in metres and may mark missing readings with NaN, “not a number.” Read the sensor’s encoding before converting.

Optional: optical depth and ROS representations

Optical Z is the forward component of distance. Ray range is the full straight-line distance to the point; away from the image center it is longer than optical Z. ROS is Robot Operating System; its depth-image specification, REP 118, describes floating-point metre values and a raw integer millimetre representation. The sensor’s actual encoding determines which rule to use.

A box contains foreground, the visible target surface, as well as floor, edges, and missing samples. A valid sample passes the sensor's validity rules. A median is the middle value after sorting valid samples. With an even count, average the two middle values: for [1048, 1050, 1051, 1052], the median is (1050+1051)/2 = 1050.5. If too few values are valid, report low evidence instead of pretending the statistic is trustworthy.

Optional: percentiles and the p90 control

A percentile is a chosen point in that sorted distribution; p90 means the 90th percentile. In this lesson, the nearest-rank p90 is the value at rank ceil(0.90 × n): ceil means round upward, and n is the count of valid samples. A rank counts positions starting at 1, so rank 1 selects the smallest valid reading. For five readings, ceil(0.90×5) = ceil(4.5) = 5: select the fifth value. With no valid readings, neither statistic can be calculated. For the illustrative millimetre values [1048, 1050, 1051, 1052, 1062, 0], discard the invalid zero: the median is 1051 mm, while the nearest-rank p90 is 1062 mm. The median describes a typical sample; p90 exposes a high-depth tail.

3. Decide whether a comparison is meaningful

“Nearer than the floor” is not universally the same as “taller than the floor.” With a level, overhead-like view, a raised cube often has lower optical Z than the floor behind it. With an oblique (slanted) camera, the floor itself has changing Z across the image. A sound height test first models the floor plane, an ideal flat surface in 3-D, then measures a point's distance from that plane. A single global floor depth is only an assumption that must be checked against the mounting geometry.

A predicate is a true-or-false comparison. A margin is a required gap beyond a reference value. For example, with floor depth 1500 mm and margin 20 mm, “nearer by more than the margin” means surface depth < 1500−20. The symbol < means less than. A surface at 1400 mm passes because 1400 < 1480. This compares optical depths; it does not measure height above a slanted floor.

Check the direction before writing the predicate

Under ordinary optical Z, a floor sample is 1200 mm, a nearer cube surface is 1050 mm, and the illustrative positive margin is 30 mm. Which comparison describes “nearer than the floor” for this simple setup?

Optional: how this node reads depth

Repository observationThe current node uses an approximate RGB/depth timestamp synchronizer, a component that pairs messages by nearby timestamps. It converts RGB with cv_bridge, a ROS image-message conversion package; requests depth with passthrough encoding, which preserves the source array's numeric representation; and returns early unless depth is a 2-D uint16 array. It reads intrinsics from the RGB CameraInfo message, the ROS message carrying camera calibration metadata, when available, with configured fallbacks.

Confirmed code behaviorgeometry_filter.py collects valid millimetre samples, estimates an annulus, meaning a ring around the box, for a floor median, and computes a raised mask, a boolean selection grid, with depth > floor_mm + raised_mm. Under ordinary optical Z, that sign selects farther points, not nearer raised surfaces. It is a code fact and a teaching example; it does not validate the hardware mounting, registration, or floor interpretation. When statistics are invalid or below the minimum count, decide returns KEEP, meaning allow this candidate to pass, with a low-quality reason, so sparse depth is visible rather than silently filtered.

Read the current detection node and geometry filter alongside the architecture. The code is evidence about this checkout; it is not proof that the physical depth stream is registered.
