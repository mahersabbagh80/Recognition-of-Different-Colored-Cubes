Check the export, then defend the result

Recovered and revised from the earlier course. Allow about 20 minutes. All interactive numbers are teaching examples.

Your goal: choose a check that supports the claim you want to make, then give a short, defensible project explanation. This workshop extends lesson 15 and recovers practice from archived lessons 4, 5, 8 and 9.

1. Different checks answer different questions

A checkpoint stores learned model parameters. An export represents its computation in another format, such as ONNX (Open Neural Network Exchange). Its graph describes operations and their connections. A TensorRT engine is a runtime artifact built for an execution environment. These definitions describe roles; filenames alone do not establish which model the robot loaded.

A structural check checks graph consistency. A smoke test tries a minimal execution. A numerical comparison runs two representations on identical prepared input and compares their output numbers with an agreed tolerance (permitted difference). A task check judges the final boxes against human-reviewed labels. Passing one does not automatically pass the others. ONNX checker documentation describes consistency checking; PyTorch's export tutorial demonstrates comparing exported output with the original model.

Explore what each result supports

Worked example: two exports can both load yet swap the red and blue class meanings. Even close raw numbers are insufficient if the class map or later box decoding differs. Record input preparation, output shape, class order, decoding rules and the final labelled comparison. Use the same saved input to isolate the change.

2. Replay, change one cause, check for regressions

Provenance means the origin and history of evidence: which image, model, settings and software produced a result. Replay means processing the same saved input again. A controlled intervention changes the suspected cause while holding other relevant conditions fixed. A regression is behavior that becomes worse after a change. Rollback restores a previously retained working version and its settings.

If a blue package receives a cube box, first retain that frame, its labels, model identity and thresholds. Compare the candidate and fine-tuned models on that same frame, then on the fixed evaluation set. Check real cubes too: removing the package prediction while losing distant cubes is a tradeoff, not an unconditional improvement. One corrected frame is a diagnostic example, not an independent performance estimate.

The earlier course's sticker-removal experiment is useful as a reasoning pattern: unchanged misses after removing a sticker weaken that explanation under those tested conditions. They do not identify the true cause. We retain this lesson in reasoning without treating archived M4/M5 measurements as today's result. 3. All required gates must pass

An acceptance gate is a required condition for using a candidate. If correctness and speed are both required, passing only one is insufficient. Define the targets before comparing models. The fictional example below requires both labelled-test correctness and timing on the intended device.

4. Build a 90-second explanation

Use four parts: data (what enters), computation (what transforms it), evidence (what was measured and where), and boundary (what remains unproved). For example: “The color image becomes a model input array; the detector proposes boxes and class scores. The decoder maps them back to camera coordinates. Our claim is limited to the named evaluation images and rules; live robustness needs separate evidence.” Add your actual recorded result rather than inventing a score.

Review your explanation
  • Could someone locate the exact model and images you mention?
  • Did you distinguish validation used for selection from independent testing?
  • Did you name an unresolved limitation and a controlled next experiment?
  • Could a listener tell whether you measured model speed or the whole camera pipeline?

These are self-review prompts. The page cannot judge the truth of your explanation; discuss it with your teaching agent.
