Evaluate a detector

The detector drew two boxes. Did it find two cubes, duplicate one cube, or mark the background? Count the matches before trusting a score.

Core: about 15–20 min; optional notes extraTerms explained locally

Your goal: decide which detections are correct before calculating a score, and explain what that score does not establish.

1. Reference answers come before metrics

Evaluation checks a system's predictions against reference answers. A detector predicts an object's category and image location. Its class is the category, such as red cube; its bounding box is a rectangle around the predicted object. Ground truth is the labeled reference used for comparison, usually supplied by human annotation—recording the correct class and box. These references can contain mistakes, so inspect them too.

Intersection over Union (IoU) is shared box area divided by the area covered by either box. It runs from 0 for no overlap to 1 for identical boxes. A threshold is a decision cutoff. For this lesson, a prediction can match a reference only if the class agrees and IoU is at least 0.50.

Matching pairs predictions with reference objects. In our simplified rule, process predictions from highest to lowest score (the detector's numeric support), and pair each with its best eligible unmatched reference. Each prediction and reference may be paired only once. A paired prediction is a true positive (TP). An unpaired prediction is a false positive (FP); an unpaired reference object is a false negative (FN).

Worked matching example: suppose the reference contains one green cube. A green prediction with IoU 0.80 passes the class and overlap rules: pair them, giving TP 1, FP 0, FN 0. If a second green prediction covers that same cube, it cannot reuse the matched reference and adds one FP. If there are no predictions at all, there are no TP or FP, but the unmatched cube contributes one FN.

Why a wrong class causes two counts

The blue prediction is an FP because there is no matching blue reference. The red reference remains unmatched, making an FN. One erroneous prediction can therefore contribute to both error counts. A duplicate adds an FP because the reference is already matched.

Count before summarizingA high class score or an expected color appearing somewhere in the image does not establish a correct detection. Class, location, and one-to-one matching all matter.

2. Precision and recall answer different questions

Precision asks what fraction of emitted detections were correct. Recall asks what fraction of reference objects were found. A metric is a numerical summary of performance. Neither metric alone describes every kind of error.

precision = TP / (TP + FP)
recall = TP / (TP + FN)

Worked example: 8 correct detections, 2 extra predictions, and 4 missed objects give precision 8/(8+2) = 0.80 and recall 8/(8+4) ≈ 0.667. The symbol ≈ means approximately equal. We emitted 10 predictions and had 12 reference objects; those denominators answer different questions.

If there are no predictions, the precision denominator is zero: report it as undefined, or state a chosen reporting convention. In an entirely empty reference set, recall is undefined. An empty scene can still reveal false positives. Do not present an undefined ratio as perfect performance.

What should you notice?

At 0.50: 2 TP, 1 FP, 2 FN. At 0.85: only A remains, giving precision 1 and recall 0.25. At 0: precision is 3/5 and recall 3/4. Raising the cutoff does not guarantee precision improves at every step: removing a low-score correct detection can lower it. D cannot be recovered by changing this cutoff because it has no candidate.

3. A curve and an average still need a definition

An operating point is a chosen setting, such as the cutoff used in operation. A precision–recall curve records precision and recall across score cutoffs.

Optional: AP, mAP, and benchmark conventions

Average Precision (AP) summarizes that relationship for one class, with a specified box-matching rule. It is not simply the mean of whatever precision values happen to appear on this slider.

Mean Average Precision (mAP) averages AP values. The evaluation protocol is the exact set of scoring rules, including classes, overlap thresholds, and averaging. COCO means Common Objects in Context, a dataset and evaluation benchmark. Its main detection AP averages across classes and IoU thresholds from 0.50 to 0.95 in steps of 0.05. A score at IoU 0.50 alone answers a less demanding location question. See the official COCO evaluation.

4. Find what the average hides

A slice is a subset of examples sharing a condition: a color class, a distance, or dim lighting. Occlusion means an object is partly hidden. Deployment means actual use, where conditions may differ from the development examples. Examine errors by condition, including occlusion and non-cube look-alikes.

Worked subset calculation: if 90 of 100 bright-scene objects and 2 of 10 dim-scene objects are found, dim-scene recall is 2/10 = 0.20 = 20%. Overall recall combines the counts: (90+2)/(100+10) = 92/110 ≈ 83.6%. Multiply a fraction by 100 to express it as a percentage. Do not average 90% and 20% equally: the groups contain different numbers of objects.

Interpret the default

An overall recall of 82.7% hides missing 9 of 10 dim-scene objects. Ten examples also provide limited evidence: one extra success changes the slice by 10 percentage points. Collect more representative evidence before generalizing.

Training data adjusts model parameters—the learned numeric values. Validation data guides choices such as model version and score cutoff. An untouched test set estimates performance after those choices. Freeze the examples and rules used to compare candidates, tune on validation, then assess the final choice on test. Repeatedly using test failures to change the system makes that set part of development.

Capture provenance records where, when, and how images were collected. Keep closely related frames from the same recording session together when splitting data, so near-duplicates do not make evaluation look easier than deployment.
