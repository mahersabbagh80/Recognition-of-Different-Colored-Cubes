Computer vision foundations · Lesson 09

Object detection

One cube can produce several candidate boxes. Follow the decisions that turn those candidates into the rectangles you see.

Core: about 15–20 min; optional notes extraTerms explained locally

Your goal: follow a possible object from numeric model output to a final detection, explaining the decisions along the way.

1. A detector proposes possible objects

Object detection predicts an object’s category and location in an image. A model is the learned computation producing those predictions. We will follow its output rather than inspect its internal network layers here.

A detector's raw output often contains many candidates—possible object predictions. Each has a class, meaning category; a bounding box, meaning a rectangle around a possible object; and a score, meaning the model's numeric support for that class. Inference, or a forward pass, runs the model to produce those predictions.

A one-stage detector predicts boxes and class scores directly from image features, without a separate region-proposal stage. Features are useful representations of image patterns. The model evaluates many positions and object sizes because it does not know beforehand where objects are. Several candidates may cover the same object; other candidates may cover background, regions without a target object.

2. Numbers need a box convention

Coordinates specify positions. We use x to the right, y downward, with zero at the top-left. A decoder converts the model's raw numeric representation into usable predictions. It must know the contract: the agreed meanings, order, and units of the numbers.

Corner format is (x1, y1, x2, y2): left, top, right, bottom. Center format is (cx, cy, w, h): center x, center y, width, height. For example, center (100, 80) and size (40, 20) become corners (80, 70, 120, 90). Subtract half the width/height for the first corner and add them for the second.

Normalized box coordinates are fractions of image width or height. In a 200-wide, 100-high image, the same center and size are (0.5, 0.8, 0.2, 0.2). Multiply horizontal values by 200 and vertical values by 100 to recover pixels. Equal fractions need not mean equal pixel lengths.

3. Remove weak predictions, then duplicates

Post-processing means the computations after model inference. A score threshold is a cutoff: keep only candidates whose score reaches it. The term confidence often refers to this score, but 0.8 does not automatically mean “80% of such predictions are correct.” Score calibration checks that relationship against labeled examples. It differs from camera calibration, which measures camera geometry.

Intersection over Union (IoU) measures box overlap. The intersection is their shared area. The union is the area covered by either box, counting the overlap once:

IoU = shared area / (area A + area B − shared area)

Two boxes each have area 100 and share 60. Their union is 140, so IoU is 60/140, approximately 0.429. Identical boxes have IoU 1; non-overlapping boxes have IoU 0.

Worked geometry: a 100 × 100 square has area 100×100 = 10,000 square pixels. If an equally sized square is shifted right by 40 pixels with no vertical shift, their shared width is 100−40 = 60 and shared height is 100. The shared area is 60×100 = 6,000; the union is 10,000+10,000−6,000 = 14,000. Divide shared area by union to get IoU. A shift of 100 or more leaves no shared width.

Check the extremes

Offset 0 gives IoU 1. At offset 100 or more, shared area is zero. Box size alone does not determine overlap; their relative positions matter.

Non-maximum suppression (NMS) keeps a high-scoring box and removes lower-scoring boxes whose overlap exceeds an IoU threshold. Repeat with the remaining boxes. Per-class NMS performs this separately for each category. See the official NMS definition.

Worked decision: two same-class boxes score 0.90 and 0.70 and have IoU 0.60. At a score cutoff of 0.50 both qualify. At an NMS cutoff of 0.50, keep the higher-scoring box and remove the other because 0.60 > 0.50. Raising only the score cutoff to 0.75 removes the 0.70 box before any overlap comparison.

Two cutoffs, different decisions

Try these settings

Score cutoff 0.75 rejects B before NMS. With score cutoff 0.50 and IoU cutoff 0.65, both remain. With score cutoff 0.95, neither survives. NMS can mistakenly suppress two nearby real objects; overlap alone does not prove duplication.

Optional: our exported detector’s exact array layout

ONNX (Open Neural Network Exchange) is a format for saved model computations. An export writes the model into such a format. The current documented output is a tensor, or numeric array, with shape [1, 7, 8400]: one image in the batch (group of inputs), seven values per candidate, and 8,400 candidate positions.

The fields are center x/y, width/height, and scores in the documented class order blue cube, green cube, red cube. Those four box values use the letterboxed 640×640 model-image coordinate grid, not the original camera-image grid. There is no separate objectness field in this documented seven-field layout. Objectness means a separate score for whether a candidate contains an object at all; some other detector layouts use it. YOLO, short for You Only Look Once, names a family of detectors, not one universal output format.

The current decoder transposes (reorders array axes) to read candidates, chooses each candidate's highest class score, applies the cutoff, and converts box coordinates. It reverses letterboxing—uniform resizing plus border padding—by subtracting padding and dividing by scale. It clips coordinates to image bounds, then performs per-class NMS. Read the documented export and decoder. These examples establish representation and code behavior, not live detection quality.

Trace this code: why divide by image width?

It turns a horizontal pixel length or position into a fraction of that image’s width. Vertical values instead use image height.
