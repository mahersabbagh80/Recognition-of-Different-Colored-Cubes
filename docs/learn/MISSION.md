# Mission: Build and reason about a robot vision system

## Why

I want enough machine-learning and computer-vision foundation to make, debug, and explain the colored-cube perception system myself. I also want to understand how a learned vision model becomes a dependable ROS 2 component on a robot.

## Success looks like

- I can describe images, labels, features, models, training, inference, and generalization in my own words.
- I can choose an appropriate vision task and design a defensible dataset split and evaluation.
- I can explain convolution, object-detection outputs, confidence, IoU, and depth without treating a library as magic.
- I can trace one camera frame through this project's model and ROS 2 interfaces, separating general principles from repository-specific choices.
- I can diagnose a failure by forming a testable hypothesis and naming the evidence that would confirm or reject it.

## Constraints

- Assume basic programming, Python, C++, and object-oriented programming; assume no prior ML, CV, or ROS 2 perception knowledge.
- Use focused lessons with core paths of about 15–20 minutes each (eleven main lessons and four optional robot lessons after the approved track reorganization), with light mathematics only where it clarifies an engineering decision.
- Every required exercise must run in the browser; Python is optional extension work.
- Deliver interactive HTML; printable PDFs are deferred at Maher’s request.
- Use trustworthy sources and clearly label general knowledge, repository observations, measured evidence, and unresolved hypotheses.

## Out of scope

- Deriving backpropagation or optimization proofs by hand.
- Surveying every vision architecture or replacing the current detector.
- Full 3-D pose estimation, manipulation, tracking, or navigation.
- Treating the current project implementation as proof that an underlying idea is correct.
