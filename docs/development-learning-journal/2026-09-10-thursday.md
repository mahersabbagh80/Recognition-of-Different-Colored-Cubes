## Unique names for new training experiments

**Problem and participation.** The training script previously used a fixed run name and refused a second launch. Its settings and summary evidence also had fixed filenames. Maher proposed timestamp-based names or numbered suffixes. We agreed to combine them. This change concerns output organization only; no new training run was requested or executed.

**Implementation.** Updated [run_robot_training_experiment.py](../../scripts/run_robot_training_experiment.py). The new `reserve_run_directory(parent, timestamp=None)` constructs a descriptive name with local date, time to seconds and UTC offset, for example `experiment_60ep_20260910_120000+0200`. It attempts to create the directory using `Path.mkdir()` without `exist_ok`. If it already exists, Python raises `FileExistsError`; the loop tries `_1`, then `_2`, and so on. Attempting creation directly avoids a race between checking existence and creating the directory.

After existing input checks pass, `main()` reserves a fresh directory and prints its location. Ultralytics receives its parent as `project`, its filename as `name`, and `exist_ok=True`. Here that option permits use of the directory this invocation has just reserved; the reservation function never selects an existing directory. This prevents Ultralytics from independently renaming the run and separating its outputs from our evidence.

**Inputs and outputs.** Model and dataset inputs, training hyperparameters and the existing historical run remain unchanged. The grouping parent still uses the existing Wednesday experiment directory; the new child timestamp identifies the actual launch time. `requested_settings.json` and `summary.json` now live inside each new run alongside `weights/`, `results.csv` and library artifacts. Earlier fixed evidence files are preserved. Failed runs can leave a partial directory; its existence does not imply training completed. A later launch gets a fresh name.

**Verification performed.** Executed a Python heredoc using `.venv-m2/bin/python`, imported the reservation helper, and used `tempfile.TemporaryDirectory` to make three reservations with the same supplied timestamp. Assertions checked the base name, `_1` and `_2` suffixes, preservation of a prior `summary.json` marker, and an empty newly allocated directory. All passed. Importing the module did not call `main()` and did not train a model. `git diff --check` also passed. Full training integration has not been rerun.
